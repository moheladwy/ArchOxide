# Security policy

## Supported versions

Security fixes target the current `main` branch. When reporting a problem in an older checkout or an `archoxide-git` build, include its commit or package version.

## Report a vulnerability

If GitHub shows **Report a vulnerability** on the [Security advisories page](https://github.com/moheladwy/ArchOxide/security/advisories), use it to send the report privately. Otherwise, contact the maintainer through a private channel. If you need a channel, open an [issue](https://github.com/moheladwy/ArchOxide/issues/new/choose) whose only purpose is to request private contact.

In your private report, include the affected revision, installation method, Arch Linux and terminal versions, and package source if relevant. Describe the observed behavior, prerequisites, and impact, and include relevant logs with secrets and personal data removed. Use fixture commands or a disposable installation when verifying package transactions.

Keep vulnerability details and any proof of concept private while coordinating disclosure with the maintainer. Use the [contribution guide](CONTRIBUTION.md) for ordinary bugs and feature requests.
